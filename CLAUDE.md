# Myna3D (folder Myna3D, was O-Form): rules for coding agents

Myna3D is the planned 3D modelling app of the Myna suite: an independent clone of Blender 5.2.3 LTS (no upstream remote, no merges or syncs from Blender), with Myna3D's own app template under `scripts/startup/bl_app_templates_system/oform/` (brand, icons, BIM tools, `ai.py`). It is **planned, not shipped**: no installer, not in the suite builds. Read [README.md](README.md), `docs/` (`build`, `developer`, `maintenance`, `licensing`, `user`) and `docs/BRANDING.md` first.

## Rules
- **Keep the tree huge and mostly untouched.** Change only Myna3D's own files (the `oform` template, branding, docs); do not reformat or refactor Blender sources. Do not search the whole repository (15 GB, mostly `.git` and `lib/`): scope searches to a path.
- **Binaries use Git LFS** (the `.gitattributes` filters apply to images, icons and libraries): commit icons and PNGs normally and let LFS handle them; do not add large new binaries.
- **Submodules.** `lib/windows_x64` (prebuilt libraries) always shows as modified: leave it, never `git add` it. `lib/linux_x64` is `update = none`.
- **Names and brand.** The product is Myna3D; Grove `#166040`, white three-circle mark (art generated by `MynaUI/tools/Brand`, copy the files, do not redraw). Old name "Finch"/"O-Form" appears only in identifiers and history. Licences: Blender's GPL tree stays separate from the suite's own licensing; follow `docs/licensing/`.
- **No claims without a build.** Building takes long and needs the Blender toolchain (`docs/build/`): say if you did not build. Git: add files by name, never `git add -A`; default branch `main`.
